# 真实店主试用：实施方案

目标：让 2-3 家真实餐饮店的店主，**用手机独立完成一次「建档 → 说今天发什么 → 回答几个问题 → 拿到能直接发的图文」**，并且我们能收集到他们的真实反馈。

原则：只做试用必需的；每个阶段结束都能在本地手机上看到效果；公网部署放在最后。

---

## 阶段 1：手机端前端重做

**做什么**
- 重写 `web/templates/index.html` 为手机优先的单页应用，一步一屏：
  1. **建档**（首次）：店名、品类、城市/位置、人均、招牌、卖点、营业时间、口吻
  2. **今天发什么**：内容类型用大按钮选择（上新 / 活动 / 日常 / 老板故事 / 节日 / 店铺介绍），一句话描述，补充信息（价格、时间、限量）
  3. **回答问题**：2-3 个追问，每题一个输入框，提示「可以用输入法的语音输入」，可跳过
  4. **结果**：见阶段 3
- 视觉：白底、小红书红（#FF2442）强调色、大按钮（≥44px 可点区域）、圆角卡片、系统中文字体；深色模式跟随系统
- 生成中：分阶段提示（找参考 → 列提纲 → 写正文 → 审核 → 做封面），避免 10-20 秒白屏
- 出错：友好提示 + 重试按钮，不露技术报错
- 技术：保持无构建步骤（原生 HTML/CSS/JS），不引入前端框架，部署简单

**验收**
- 在手机（375px 宽）上完整走完 4 步，无横向滚动、无需缩放
- 先出设计稿给你确认风格，再写代码

**规模**：中

---

## 阶段 2：照片上传 + 图片封面

**做什么**
- 上传：第 2 步可选 1-9 张照片（jpg/png/webp），前端压缩到长边 ≤2000px 再上传，单张 ≤5MB
- 接口：`POST /api/uploads` 存到 `outputs/uploads/<id>/`，返回图片 id；生成请求带上图片 id 列表
- 封面：服务端用 Pillow 渲染 **1080×1440（3:4）PNG** —— 第一张照片裁切铺满 + 封面大字 + 半透明底条；内置开源中文字体（思源黑体，OFL 许可）保证各设备一致
- 2-3 套封面样式可切换（大字居中 / 底部标题条 / 左上角标签）
- 没传照片时退回现有纯色文字封面（也输出 PNG）
- 其余照片原样作为内页，结果页可一起下载

**验收**
- 传一张手机实拍照片，得到清晰、文字不遮挡主体的 PNG 封面，手机上可长按保存
- 单元测试覆盖裁切比例、文字换行、无照片兜底

**规模**：中（封面排版需要调几轮）

---

## 阶段 3：结果页 + 反馈收集

**做什么**
- 结果卡片：封面预览（可左右滑看内页）、标题、正文、标签
- **一键复制**：标题 / 正文+标签 分开复制（小红书 App 里标题和正文是两个输入框）
- 下载封面和全部图片
- 「按意见重写」：输入一句话，复用现有 revise 流程
- **反馈**：每篇底部三个按钮「能直接发」「改改能发」「不能用」+ 可选一句话理由
  - 新表 `feedback(run_id, shop_code, rating, comment, created_at)`
  - 记录「复制了没有」「下载了没有」作为隐性信号
- 评测工具加一个导出：按店、按内容类型汇总反馈

**验收**
- 手机上复制后粘贴到小红书 App，格式（换行、emoji、#标签）正确
- 反馈写进数据库，能按店查到

**规模**：小-中

---

## 阶段 4：试用码 + 店铺档案存服务端

一个设计同时解决「访问控制」「档案不丢」「额度控制」「反馈归属」四件事：**每家试用店发一个试用码**。

**做什么**
- 新表 `shops(code, profile JSONB, daily_limit, created_at)`
- 首次打开输入试用码 → 服务端存/取该店档案；换手机输入同一个码即可恢复
- 所有接口校验试用码；每个码每天生成次数上限（默认 20），超了友好提示
- 管理命令：`xhs-db shop add --name 巷口小馆` 生成试用码；`xhs-db shop list` 看用量和反馈
- 运行记录 `runs` 关联试用码

**验收**
- 无码/错码无法生成；超额被拦；换浏览器输入同一个码档案还在

**规模**：小-中

---

## 阶段 5：本地整体验收

- 你用自己的手机（连电脑同一 Wi-Fi，访问电脑局域网地址）按真实店主的方式完整走 3-5 次
- 用真实照片、真实的店（或熟悉的店）测试
- 修掉体验问题后再进入部署

---

## 阶段 6：部署到公网（最后做）

**部署前需要先确认**
- VPS 资源偏紧，应用本身预计占 150-250MB 内存，需要实测
- 域名：需要一个你的域名/子域名，用于 HTTPS（小红书、微信里打开链接都要求 HTTPS）
- VPS 上的 80/443 端口已被其他服务的反向代理占用，需要在已有代理里加站点，届时单独确认

**做什么**
- 应用打包成 Docker 镜像，和 `xhs-agent-postgres` 放在同一个 compose 网络里（不再需要 SSH 隧道）
- `.env` 生产配置放在 VPS 上（权限 600），Key 不进镜像
- nginx 反代 + HTTPS 证书
- 上传图片和封面的磁盘上限与定期清理
- 部署后在手机上走一遍完整流程

**规模**：中（主要是 VPS 上的配置和排查）

---

## 阶段 7：真实试用

- 2-3 家店，建议你在旁边看他们用第一次：卡在哪一步、看到结果的第一反应、会不会真的发出去
- 试用 1-2 周后看：生成了几篇、「能直接发」比例、实际发出去几篇、店主愿不愿意继续用
- 这些数字就是简历和后续方向（多平台、拍摄脚本）最有说服力的依据

---

## 需要你决定的事

1. **风格确认**：阶段 1 开始前我先出手机端设计稿
2. **域名**：阶段 6 之前准备好（没有的话可以先用 IP + 自签证书内测，但微信里打开会有警告）
3. **试用店**：2-3 家，最好品类不同（例如一家正餐、一家咖啡/甜品）
