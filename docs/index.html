值得一看的设计

防编造审核

正文里带单位的数字（价格、折扣、份数、时间）和「半价 / 免费 / 买一送一」必须能在店铺档案、本次需求或店主回答里找到，否则打回并带着具体问题重写。24 个评测用例零编造。

素材追问

动笔前让模型问店主只有他知道的细节；回答既是素材，也算进「允许出现的事实」。提示词强制第一人称，避免「店主说……」的 AI 转述腔。

真实进度（SSE）

LangGraph 每完成一个节点推一条事件，前端逐项打勾；审核不通过会显示「正在改写」。流式模式也用来兼容只支持流式的模型中转。

试用码体系

一个 6 位码同时管访问、服务端店铺档案、每日额度（生成和重写计次、原子扣减）、反馈归属和店与店隔离。

照片封面

上传时摆正方向、压缩、去 EXIF 定位；1080×1440 PNG 三种样式，中文按行长平衡断行，避免孤字。

局限：裁判与生成同为 DeepSeek（自评偏差），每组只跑一次，样本小，±0.2 以内视为噪声。完整数据和发现见 评测报告。

真实试用学到的

问题预设会变成「事实」

问「有没有一位几乎每周都来的老客」，店主只答了他点什么，文案却写成「几乎每周都来」。数字规则查不出这种语义越界——下一步需要 LLM 审核层或换提问方式。

写文案不是护城河

店主用通用聊天机器人也能得到差不多的文案；在小红书上图片比文字重要。这是项目停在试用前、没有继续加功能的原因。
