# 评测报告

所有数字来自 `evals/run_eval.py` 的真实运行（原始明细在本地 `evals/results/`，未入库）。
生成模型 `deepseek-flash`；裁判也是同一模型——**存在自评偏差**，且每组只跑一次、样本量小（24-40），
小于 ±0.2 的差异应视为噪声。

## 评测怎么做

| 层 | 内容 |
|---|---|
| 规则指标 | 生成成功、审核一次通过、标题 ≤20 字、标签数、紧扣选题（重叠二元组覆盖率）；商家用例另加「提到店名/招牌」「无编造」 |
| LLM 裁判 | 通用：吸引力 / 相关性 / 实用性 / 口吻；商家：吸引力 / 相关性 / 想去店里 / 像店主，**带分档标准的严格打分**（见下「裁判太松」） |
| 模拟店主 | `--interview`：每个商家用例带一段只有店主知道的 `owner_notes`，Agent 自己提问，模拟店主据此回答，答不上的不编 |
| 用例 | 通用 40 个选题（13 品类）；餐饮 24 个（8 家虚构店 × 3 个需求：上新 / 活动 / 日常 / 老板故事 / 节日 / 店铺介绍） |

## 1. 通用选题：检索真实笔记有没有用？

同一 prompt，只换参考笔记库：

| 参考库 | 一次通过 | 吸引力 | 相关性 | 实用性 | 口吻 |
|---|---|---|---|---|---|
| 12 条自编示例 + 字面匹配 | 90% | 4.38 | 4.90 | 4.85 | 4.92 |
| 91 条真实笔记 + 向量检索 | 82.5% | 4.28 | 5.00 | 4.85 | 4.90 |

**结论：测不出差异。** 更重要的发现是**裁判太松**——80 篇全是 4-5 分，量不出好坏。
后面的商家评测因此换成了带分档标准的严格裁判（5 = 明显优于同行，3 = 及格但模板感重）。

## 2. 餐饮商家：逐步迭代

24 个用例，每行只改一个变量：

| 版本 | 改了什么 | 一次通过 | 无编造 | 吸引力 | 相关性 | 想去店里 | 像店主 |
|---|---|---|---|---|---|---|---|
| v1 | 商家模式基线 | 87.5% | 100% | 3.00 | 4.33 | 3.04 | 3.04 |
| v2 | prompt 去模板感：信息挑 2-3 条别罗列、卖点进标题、允许写口感、禁套话 | 95.8% | 100% | **3.67** | **4.71** | **3.88** | **3.96** |
| v2 + 餐饮库 | 参考笔记换成 109 条餐饮笔记（55% 商家号） | 87.5% | 100% | 3.58 | 4.67 | 4.00 | 4.00 |
| v3 | 结尾一句话带出店名位置；活动规则写全 | **100%** | 100% | 3.75 | **4.79** | **4.17** | **4.25** |
| v3 + 追问 | 动笔前问店主 2-3 个问题（模拟店主回答，平均 1.6 条） | 95.5%¹ | 100%¹ | 3.70 | 4.35 | 3.90 | 4.15 |

¹ 该组 2 个用例因评测进行中删除了旧模板文件而中断，按 22 个有效用例计；裁判有效 20 个。

**结论**
- **起作用的是 prompt**：v1→v2 各维度 +0.4~0.9，是全程最大的提升。
- **换参考库、加追问都没有测出提升**（差异在噪声内）。追问在模拟里甚至略降——裁判看到更多事实后要求更高，
  且模拟店主的回答很单薄。追问是否有用，需要真实店主验证，模拟评测回答不了。
- **防编造 100%**：24 个用例里价格、折扣、时间、优惠说法没有一处超出给定信息（审核会拦下并带着问题重写）。

## 3. 评测过程中发现并修掉的问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 每篇都要重写一次，耗时 16s → 实际应 9s | 「第一步」「第一碗」被敏感词「第一」误判 | 词表支持 `!` 开头的放行短语 |
| 模型输出偶尔多一段文字，整次运行崩溃 | JSON 解析过严 | 容忍前后多余文字 + 带错误信息重试 + 失败以 `status=error` 结束 |
| 「凌晨 2 点」「晚上 11 点」被当成编造 | 事实里写的是 `02:00` / `23:00` | 时间归一化（去前导零、24 小时制换算） |
| 加追问后「像店主」反而下降 | 模型把店主回答写成「店主说……」的转述 | prompt 明确：店主补充就是「我们」自己的话，用第一人称 |
| 有了故事就忘了店名和位置，相关性掉 0.5 | 「别罗列信息」被理解过头 | v3：结尾一句话带出，不列信息块 |
| 「紧扣选题」指标误判 | 选题按不重叠二元组切（「人一」「周带」） | 改为重叠二元组覆盖率 |
| 裁判全给 4-5 分 | 评分标准太宽 | 商家评测换严格分档 |

## 4. 已知但未解决

- **追问的「问题预设」会被当成事实。** 真实试用中问「有没有一位几乎每周都来的老客」，店主只答了点什么，
  文案却写成「几乎每周都来」。防编造规则只查数字和优惠，查不到这类语义上的越界；需要 LLM 审核层或改提问方式。
- 裁判与生成同源（DeepSeek 自评）；正式对比应换异源裁判或做两两对比（pairwise）。
- 封面是「照片 + 大字」模板，与小红书真实餐饮封面（多图拼接、贴纸、手写字）差距明显。

> 我们家的米饭免费续。所以这道菜的汁千万别浪费，一碗接一碗添起来才过瘾。

> 秋刀鱼是那种很看时令的鱼，秋天的油脂最足。烤过之后皮是脆的，肉还是软的，一筷子下去能闻到带点焦香的油润味……
